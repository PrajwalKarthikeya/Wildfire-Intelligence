# Phase 11 Journey Journal: The $0 Production Deployment

We have built a sprawling, highly-intelligent local application. In Phase 11, we prepared it to live on the internet so you can actually put a live URL on your resume—without spending a single dollar.

---

## 🧑‍🏫 Layman's Terms

When you build a project on your laptop, nobody else can see it. "Deployment" is the process of putting your code onto computers that run 24/7 (servers) so anyone in the world can type a URL into their browser and see your dashboard.

Usually, running an AI engine, a database, a backend server, and a frontend website costs money. But we architected this specifically to fit into the "Free Tiers" of modern cloud providers.

1. **The Database**: We set up the code so you can easily swap our local SQLite file for a massive cloud database provided for free by **Supabase**.
2. **The Backend**: We added a special `Procfile` so a free hosting service like **Render** or **Railway** knows exactly how to start our FastAPI "Librarian."
3. **The Data Refresh Engine**: Instead of paying for a computer to stay awake 24/7 just to fetch NASA data every 15 minutes, we tricked **GitHub Actions** into doing it for free! It will wake up on a schedule, run our Python scripts, update the Database, and go back to sleep.
4. **The Frontend**: The React Dashboard generated by Open Code is perfectly primed to be dragged and dropped into **Vercel** for lightning-fast, free hosting.

---

## 👩‍💻 Technical Terms

To facilitate a $0 deployment architecture, we prepared the repository with the necessary infrastructure-as-code files.

### 1. Dependency Standardization
*   **Action**: Rewrote `requirements.txt` to strictly include only our core production dependencies (`fastapi`, `uvicorn`, `scikit-learn`, `SQLAlchemy`, etc.). This ensures container builds on Render/Railway will not bloat or fail.

### 2. CI/CD Orchestration (The $0 Worker)
*   **Action**: Authored `.github/workflows/refresh_pipeline.yml`.
*   **Strategy**: Cloud providers charge money for always-on background workers. To bypass this, we implemented a CRON-triggered GitHub Actions workflow that executes every 15 minutes. It spins up an ephemeral Ubuntu runner, injects your NASA/Database secrets, executes the data pipeline, and spins down. Zero cost compute.

### 3. Server Gateway Interface
*   **Action**: Created a `Procfile` containing `web: uvicorn backend.main:app --host 0.0.0.0 --port $PORT`.
*   **Strategy**: This file is the universal standard instructing PaaS providers (Render, Heroku, Railway) on how to bind the ASGI server to their dynamically allocated network ports.

### The Result
The repository is perfectly staged for deployment.
